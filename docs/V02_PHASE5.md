# v0.2 Phase 5 — Bounded proactivity and native notification outbox

Goals reuse the existing native Schedule coordinator, lifetime/step/time/token limits, consented memory injection, report tool, durable Session result references and persisted finding fingerprints. A repeated finding or `changed=false` does not create another Inbox notice. The managed plugin does not create a second inference loop. Product goals link to the original native task and pause/cancel through it.

The native mobile notification channel now observes the original persistent Inbox. It never replaces Inbox or marks a task complete. A separate private gateway schema migrates from version 1 to 2 for notification subscriptions, deliveries and acknowledgments; the existing core database is unchanged. Configuration is fail-closed: `ALWAYS_ON_EXPO_PUSH_ENABLED=1`, a real `ALWAYS_ON_EXPO_PROJECT_ID` and server-only `ALWAYS_ON_EXPO_ACCESS_TOKEN` are required. Enable enhanced push security for that Expo project; provide its actual APNs/FCM credentials through Expo's authorized account configuration. Never put provider access/model keys in mobile environment variables or this public repository.

Only an authenticated device can register/disable its subscription or acknowledge its own delivery. Revocation disables its push subscription. New registrations do not replay the historical Inbox backlog. Payloads contain a generic update message plus the authority and notice IDs, not research findings, memory or model credentials. The phone validates authority identity, opens the corresponding persistent Inbox record and may acknowledge foreground receipt or a user open.

Delivery state deliberately distinguishes `pending`, durable `sending`, Expo ticket `accepted`, APNs/FCM handoff `provider_confirmed`, `failed`, transport/crash `unknown` and client-reported `device_acknowledged`. An ambiguous send or interrupted send is not automatically replayed. Receipt queries may retry read-only, with an expiry cutoff; a ticket or provider receipt never certifies that the user received or saw a system notification. Dedupe is per paired device and Inbox notice. Expired provider registrations are disabled. Inbox survives every push failure. Outbox storage has a hard admission cap; no unsafe automatic deletion of deduplication records is performed.

`tests/unit/native-push.test.ts` injects labeled transport fixtures to verify those state distinctions, deduplication, timeout ambiguity, revocation and missing-configuration behavior. These tests are not production push acceptance. Real APNs/FCM delivery and device receipt remain blocked until project provisioning, signed physical builds, user permission and actual devices are available.

The managed workflow additionally runs `scripts/verify-real-deepseek.mjs`. Configure Actions secret `ALWAYS_ON_DEEPSEEK_API_KEY` and variable `ALWAYS_ON_DEEPSEEK_MODEL` with an officially supported model ID. With both present, the gate launches only the pinned native `deepseek-official` provider and verifies an offline native scheduled run, business report, durable Session usage/terminal events, Inbox and restart recovery. Without credentials it writes an explicit blocked artifact; it never substitutes a fixture model. This gate alone is not the complete release chain.

**MVP Ready remains false** until the actual phone → actual Desktop → Desktop powered off → continuously hosted real DeepSeek execution → physical native push → identical Session/result chain is recorded.

Operator deployment also caps the pinned native auxiliary search provider at 512 output tokens and one server search use per request. Auxiliary provider billing is separate from the main model's reported token ledger; use provider spending limits in addition to the task's run/step/time/token caps. Those caps do not promise an exact monetary charge or instantaneous cancellation of an already dispatched request.

The mobile Devices page can read its own delivery state and disable push. Notification taps resolve the persistent Inbox notice and run by ID, even when the run has fallen outside the latest 200-row snapshot; the app then opens that authority's native Session. The real-provider verification also checks this notice/run lookup chain when configured. Oversized outbox admission is visible through status and never deletes Inbox. Malformed successful HTTP responses are classified as unknown, not assumed provider rejection.

Historical mobile result views bind the run's durable terminal reference to the public Session `beforeSeq` cursor and display that run's own summary, status and sources. Polling does not silently switch the view to a later execution of the same task. Returning to live conversation is explicit. The real Harness protocol test exercises the exclusive historical-event boundary; this is protocol evidence, not a real-model or physical-phone result.
