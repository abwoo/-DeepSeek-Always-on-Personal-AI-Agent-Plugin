# v0.2 security review scope

The managed authority is a single-owner Harness profile. Device bearer tokens are individually expiring/revocable; only hashes are stored on the Host. A trusted TLS edge exposes the narrow `/personal-agent/v1/*` API, not the native owner/API port. The actual container test verifies certificate validation, denied owner routes, denied unauthenticated device access, console pairing and matching authority identity. This is a private CI test certificate, not a deployed public certificate or a continuously hosted service.

Native phone secrets use OS-backed Expo SecureStore, including an actual startup write/read/delete check. Desktop stores its device credential through Harness's public credentials provider; the renderer receives metadata, not bearer/model keys. No model key belongs in phone configuration. Both clients preserve uncertain operation metadata instead of automatically repeating writes. Scheduled tasks retain the original read-only tool guard, native approval boundary and bounded budgets. There is no desktop-local file/action bridge.

A full root npm audit initially found vulnerable transitive dependencies. Compatible operator pins now resolve `undici` 8.12.2, `fflate` 0.8.3 and `@modelcontextprotocol/client` 2.3.0 while leaving Harness 0.2.2-rc.3 and Cordis 4.1.0 fixed. Mobile build tooling pins `@expo/fingerprint`'s `minimatch` to 11.0.1. Local audit summaries and CI validation are recorded in `docs/evidence/security/npm-audit-summary.json`. Zero reported npm advisories applies only to those installed dependency graphs at that time; it is not a comprehensive security certification.

The actual signed official Desktop binaries separately report bundled `undici` 8.11.2 and MCP client 2.2.0. These fall within published advisory ranges (GHSA-2m5v-pch6-74hx and GHSA-6prh-2h8m-c8cw, among related undici advisories). Presence does not establish exploitability through this plugin, but operator npm overrides do not patch the signed Desktop application. Vendor remediation or a documented, reviewed exposure assessment remains a production security gate. This project does not modify or re-sign the official Harness core to conceal that gap. A future official-version upgrade must repeat native compatibility validation.

Secrets, SQLite state and mobile signing material are excluded from git/EAS/container uploads. Server logs redact launch/model/provider credentials. Deployment still requires private durable storage, one writer/replica, backups, provider spending limits and operational monitoring. Public deployment assessment, physical device/OS testing, full approval UX, current upstream Desktop exposure assessment and the complete real-provider/native-push chain are not accepted. **MVP Ready remains false.**
